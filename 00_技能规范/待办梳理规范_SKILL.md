# 待办梳理规范（SKILL）

> 用途：把散落在**项目清单、会议纪要、周报、IM/邮件与脑子里**的未完成事项，抽取并收敛成**唯一一份待办主清单**。
> 适用目录：`05_绩效与团队管理/计划模板/`
> 配套模板：`05_绩效与团队管理/计划模板/待办主清单模板.md`（管"有哪些事"）
> 配套方法：`05_绩效与团队管理/计划模板/工作投入比例与每日时间预算_方法与模板.md`（管"每天各域花多久"）
> 🔑 核心原则：**先无过滤倾倒 → 再切换视角扩展 → 最后才分类收敛**。顺序颠倒 = 系统性遗漏。

---

## 一、为什么"直接想我有哪些待办"会失败

| 失败原因 | 表现 |
| --- | --- |
| 记忆偏置 | 大脑只吐出最近、最吵的事（几乎全是救火项） |
| 无触发点 | 长期项、跨月项、欠别人的口头承诺天然不被想起 |
| 无抽取动作 | 待办散落在 N 个文件里，从不被"提"到一处，所以永远没有全貌 |
| 边想边分类 | 分类动作打断联想，一分类就"卡住想不出"了 |

> 结论：**待办不是想出来的，是"扫"出来的。** 靠换视角，不靠努力回忆。

---

## 二、三入口扫描（启动动作）

从这三个入口分别扫描，能唤起**完全不同批次的记忆**：

| 入口 | 触发提问 | 挖出的典型内容 |
| --- | --- | --- |
| **角色/身份** | 我同时是哪几个身份？每个身份欠着什么？ | 项目经理 / 团队负责人 / BU 统筹 / 个人专业成长 / 对外客户 |
| **承诺** | 我答应过谁什么？谁答应过我什么？ | 最容易被忘、但代价最大的一类（信用成本） |
| **痛点** | 什么让我烦、重复、卡住、被动救火？ | 每个"痛"背后都是一条没被立项的待办 |

## 三、五视角扩展（思维拓展的核心）

**规则：一次只用一个视角，写完再换下一个；期间绝对不要分类、不要排序、不要判断该不该做。**
建议载体：白板 / 思维导图 / 纯粹的 Inbox 清单，先做**放射**，收敛留到第四节。

### 1. 时间地平线
- 今天必须动的是什么？
- 本周要交付的是什么？
- 本月要收口的是什么？
- 本季度只推进一件事的话，是哪件？
- 今年年底回看，哪件事没做会后悔？

### 2. 状态
- 还没启动的有哪些？
- 进行中但**卡住**的有哪些？卡在谁/什么上？
- 在**等别人**的有哪些？我上次催是什么时候？
- 我**已经答应但没交付**的有哪些？（最危险的一类）
- 想做但一直没立项的有哪些？

### 3. 对象
- 逐个在研项目扫一遍：这个项目上欠谁的、缺什么文档、下一个里程碑是什么？
- 逐个下属扫一遍：谁需要我做什么？谁需要被推一把？
- 逐个客户/对接方扫一遍：谁在等我的答复？

### 4. 缺口
- 缺**知识**：哪个技术点我一直在绕？
- 缺**流程/规范**：哪件事每次都靠我临时救？
- 缺**模板/工具**：哪些文档我重复造轮子？
- 缺**人/设备/权限**：什么东西申请了但没到位？

### 5. 反向（最能腾出空间，几乎没人主动问）
- **如果我什么都不做，会发生什么？** 哪些其实不会有事？
- 哪些该**停止**？哪些该**推掉/退回**？哪些该**委派**给谁？
- 哪些是我"惯性在做"但已经不该由我做的？

## 四、收敛规则

### 4.1 每条待办的三要素写法

**动词 + 对象 + 完成判据（可验收）**

| ❌ 不可执行 | ✅ 可执行 |
| --- | --- |
| 整理需求文档 | 把 SR/AR 拆分表补齐并发出给客户确认 |
| 跟进美泰方案 | 拿到美泰对 V1.3 方案的书面反馈 |
| 优化周报 | 把周报数据源改成 modules 结构并跑通一周 |

### 4.2 只分两类，不要混着写

- **下一步具体动作**：≤30 分钟能做完的单步动作
- **项目 / 成果**：需要多步交付的结果（其下再挂"下一步动作"）

### 4.3 状态枚举（统一用词）

`未启动` / `进行中` / `卡住` / `等待中` / `已完成` / `已取消`

### 4.4 优先级

用**「影响 × 紧急」两列各 1–5 分**打分后排序（表格里可排序、可筛选），**不要画四象限图**——图上放不下理由，且无法回查。

### 4.5 去重与拆解

- 同一件事在多处出现 → 合并为一条，把来源记在备注
- 一条超过 2 小时的工作 → 拆到"下一步动作"粒度

## 五、落地与周期化

1. **唯一主清单**：只认一份。会议纪要、IM、邮件、周报一律视为"来源"，不视为清单。
2. **Inbox 必清空**：任何灵感先扔进「待归类暂存区」，每轮梳理结束前必须清空。
3. **每周固定 15 分钟节律**：扫描来源 → 补入 Inbox → 收敛分类 → 清空 Inbox → 标记本周 TOP3。
4. **整理一次会乱，周期化才不塌。**
5. **每条待办标所属工作域**：按《工作投入比例与每日时间预算》给工作域编号（A–H），当天只处理"今日时段对应域"的条目，避免清单有了却不落到工时。

## 六、常见失败模式（自查）

- 边扫边分类 → 联想中断，扫不全
- 全写成"整理 XX / 跟进 XX" → 清单好看但无法执行
- 只记"事"不记"人等" → 催办全部漏掉
- 从不做反向视角 → 清单只增不减，最终放弃
- 多份清单并存 → 回到"没有全貌"的原点
- 只梳理不复查 → 一周后清单过期，等于没做

---

## 七、AI 协作方式

- 交给 AI 的：**从已有资产中抽取候选待办**、按「角色/状态/对象」预分类、把粗条目改写成三要素写法、查重合并。
- 不交给 AI 的：**影响/紧急打分、该不该做、该停止什么**——这三个必须本人决定。
- 提示词骨架：`按《待办梳理规范（SKILL）》扫描 <来源文件/目录>，抽取候选待办，输出到主清单模板的对应分区，不要替我打优先级。`
