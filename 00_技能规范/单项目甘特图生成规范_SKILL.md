# 单项目甘特图生成规范（HTML + XLSX）· SKILL

> 用途：为**单个项目**生成排期甘特图 —— ① HTML 可视化（展示任务、负责人、起止日期、里程碑、前后置依赖），② XLSX 进度表格（汇报/存档）。本规范汇总所有甘特图相关约定，后续直接按此执行。
>
> 目录：`03_项目管理与模板/05_项目管理工具/`
> 参考实现：`01_甘特图/安路项目_甘特图_20260801.html`、`01_甘特图/安路项目_甘特图_20260817.xlsx`（26088 安路科技 FPGA BI 测试项目）

---

## 一、何时使用

- 需要把单个项目的排期可视化（含负责人、里程碑、依赖链），供团队/客户查看。
- 需要把排期导出为 Excel 进度表格用于汇报、存档。
- 数据**同源**：HTML 内 `TASKS` 数组是唯一数据源；XLSX 由脚本基于同源数据生成，两者保持一致。

## 三、HTML 生成规范

### 3.1 数据模型（核心）

```js
const RANGE = { start:'2026-07-31', end:'2026-09-07' };   // 时间轴范围（含首尾）
const TODAY = '2026-08-17';                               // 今日线位置

const TASKS = [
  { group:'硬件', name:'Layout 工作', assignee:'龙学兵',
    start:'2026-07-31', end:'2026-08-07', status:'done', key:true,
    depFrom:'硬件原理图 FIX', note:'已完成，关键路径' },
  { group:'软件', name:'软件开发 · 1.1 Bitstream文件解析', assignee:'蒋文龙',
    start:'2026-08-10', end:'2026-08-11', status:'done', note:'2 天' },
  // 未排期任务用 start:null, end:null, status:'tbd'
];
```

| 字段 | 说明 |
| --- | --- |
| `group` | 分组名（如 硬件 / 软件），渲染组标题行 |
| `name` | 任务名 —— 必须是**真实任务项** |
| `assignee` | 负责人；无负责人用 `'—'` |
| `start` / `end` | 绝对日期 `YYYY-MM-DD` |
| `status` | `done` 已完成 / `ongoing` 进行中 / `todo` 待开始 / `warn` 关键风险 / `tbd` 未排期 |
| `mile` | 里程碑（渲染为菱形 ◆） |
| `key` | 关键路径任务（左侧 ★ + 统计"关键/风险"） |
| `depFrom` | 前置任务 `name`，用于依赖标记与"↳ 前置"标签 |
| `note` | 备注，悬停 tooltip 显示 |

### 3.2 状态配色（HTML 与 XLSX 统一）

| status | 颜色 | 用途 |
| --- | --- | --- |
| done | 绿 `#52c41a` | 已完成 |
| ongoing | 蓝 `#1890ff` | 进行中 |
| todo | 灰蓝 `#b0b8c4` | 待开始 |
| warn | 橙 `#fa8c16` | 关键/风险 |
| tbd | 虚线灰 | 未排期 |

### 3.3 依赖关系表达（重要经验）

- ❌ **不要**用跨工作条的折线/贝塞尔箭头连接前后置 —— 多任务常从同一起点开始（时间重叠），折线会横穿工作条、杂乱难看（已在安路项目踩坑放弃）。
- ✅ 用**端部轻量标记**：任务条左端橙色圆点 `●`（承接前置）、右端白色小三角 `▸`（交付后置）、条内 `↳ 前置：xxx` 文字、图例依赖链。
- ⚠️ "后置工作"这类描述性阶段**不要**建成独立任务条，用 `depFrom` 让后置任务直接指向前置任务。

### 3.4 页面功能

- 头部：项目编号 / 项目经理 / 商务 / 更新时间 / 本周进展一句话。
- 统计卡：任务总数 / 已完成 / 进行中 / 待开始 / 关键风险。
- 图例：状态色块 + 端部标记说明 + 依赖链。
- 甘特主体：左标签列（约 270px，组标题 26px / 任务行 42px，与右侧严格对齐）+ 右轨道列（日网格：周末浅灰、今日列红色高亮）+ 任务条 + 今日线。
- 时间轴：周 / 日双行，支持缩放切换；今日线贯穿全图。
- 任务条定位：`left = (start − rangeStart) / 总天数 × 100%`，`width = 天数占比`。

### 3.5 宽度自适应（已实现，勿回退到固定格宽）

- `cellW()` 按右侧可视区**动态填满**：日视图 22~80px/天、周视图 36~120px/天；窗口过窄时保持最小可读宽度并横向滚动。
- 窗口 `resize` 防抖（约 120ms）重渲染。
- **首次渲染必须延迟到 `load` 后**（否则 `gRight.clientWidth=0`，会回退到最小宽度导致图表卡窄）：用 `load + setTimeout(bootRender,0)` 触发，并加 `setTimeout(bootRender,500)` 兜底确保一定执行（**勿用 requestAnimationFrame**，部分环境不触发导致图表不渲染，已在金泰克踩坑）。
- `.g-right{overflow-x:auto; min-width:0}` 防 flex 撑开；`cellW()` 加窗口宽度兜底 `window.innerWidth-320`。
- 左列任务名加 `.tname`（`flex:1;min-width:0;overflow:hidden;text-overflow:ellipsis`）超长省略，完整名悬浮显示。
- 响应式断点：≤1100px 左列 220px、≤700px 左列 160px 且隐藏负责人列。

### 3.6 去 AI 味要点

- 不用 emoji（`📊 ✅ ⚠️ 🔧 💻` 等）、不堆装饰标签（如"P1"徽标、"● 进行中"胶囊）。
- 文案口语化，像人工维护的管理记录；图例/里程碑/排期说明精简。
- 参考已优化文件：`01_甘特图/安路项目_甘特图_20260801.html`。

## 四、XLSX 生成规范（甘特进度表格）

- 脚本：`02_脚本/generate_anlu_gantt_xlsx_new.py`（openpyxl，数据与 HTML `TASKS` 同步）
  - 旧文件 `generate_anlu_gantt_xlsx.py` 仍为 20260817 旧数据，当前统一用 `generate_anlu_gantt_xlsx_new.py`；后续如恢复原文件名，删除旧脚本后重命名新脚本即可
- 运行：`python generate_anlu_gantt_xlsx_new.py YYYYMMDD`
  - 用完整 Python 路径：`C:/Users/pc/AppData/Local/Python/pythoncore-3.14-64/python.exe`（openpyxl 3.1.5）
- 输出：`01_甘特图/安路项目_甘特图_<日期>.xlsx`

### Sheet 结构（**不含"说明"sheet**，说明统一在此 SKILL）

1. **甘特图**：进度表格主表
2. **任务清单**：明细表（序号/线/任务/负责人/起止/工期/状态/前置/备注）
3. **关键里程碑**：日期 + 节点 + 状态

### 进度表格样式（参考 `01_甘特图/项目总览与甘特图.xlsx` 的「甘特-AL-FPGA BI 测试」表）

- 布局：左侧任务名称（带 `[完成]/[进行]/[待办]` 状态前缀、分组标题行浅蓝 `EEF2F7`）+ 右侧**每天一列**，任务时间范围用彩色单元格填充。
- 表头：第 1 行标题（深蓝 `2F5496` 底白字）、第 2 行时间范围、第 3 行天序号（1~N）、第 4 行日期（每天 `M/D`，周末浅灰 `F7F9FB`、今日红底 `FFF1F0` 红字 `CF1322` 高亮）、第 5 行月份标签（如 `8月`，棕红 `C0504D`）+ 周标签（如 `W31`，深蓝 `2F5496`，周首列加粗竖线；范围首日也放周标签）。
- 颜色：完成绿 `52C41A` / 进行蓝 `1890FF` / 待办灰 `B0B8C4` / 关键橙 `FA8C16` / 延期黄 `FADB14`；周末列浅灰 `F7F9FB`；任务名底色随状态（绿 `F6FFED`/蓝 `E6F7FF`/灰 `F5F5F5`/橙 `FFF7E6`/延期 `FFFBE6`）。
- 冻结窗格 `B6`；A 列宽 46、日期列宽 4.2；细边框 `D9D9D9`。
- 任务名前缀去模块前缀（`软件开发 · `、`应用开发 · `）只保留子任务名，便于左列阅读。

### 4.4 甘特图 + 项目计划（表内公式自更新版，紫荆芯界 / 闪迪在用）

区别于上面的"静态填色表"：这类表把**结束日期、预警、甘特条颜色、看板统计全部做成公式 + 条件格式**，日常只改开始日期 / 工期 / 状态（闪迪再加实际完成）。**页面标题就叫「项目计划与甘特图」，不要写"智能甘特图"这类自造词。**

- 生成脚本：`02_脚本/generate_zijing_schedule_xlsx.py`（紫荆：工作日口径 + 工作日历）、`02_脚本/generate_sandisk_schedule_xlsx.py`（闪迪：计划开始 / 预期完成 / 实际完成 三日期）
- 输出：`01_项目目录/10_紫荆芯界/`、`01_项目目录/09_SD高可靠性SLT项目/` 下的 `…_项目计划_V<n>_<YYYYMMDD>.xlsx`
- 版式：B~M 为信息列（序号/工作项/负责人/开始日期/**工期(工作日)**/**计划结束**/**实际结束**/**偏差(工作日)**/工期(自然日)/状态/预警/备注），N 起逐日一列；每月之间插 1 列隐藏窄列，日期列设 `outlineLevel=1`，配合 `Outline(summaryRight=True)` 实现「列上方 +/− 展开收起单月」。
- **必须有「实际结束」列**，否则大家一 delay 计划表就失真（计划结束是算出来的，不会因为延误而变）：
  - `实际结束` 手工填，完成当天录入、未完成留空；列底色浅红，提示这是要人填的列。
  - `偏差(工作日)` 三态：填了实际 → `NETWORKDAYS(计划,实际)-1`（提前则取负）；未完成且过期 → `NETWORKDAYS(计划,今天)-1`；未到期 → 空。**状态标已完成但没填日期时不给偏差**，只提示「⚠ 待填实际日期」，避免统计被污染。
  - 甘特条必须是五段：绿=按期完成、**橙=超期完成段（计划结束→实际结束）**、红=延期中（计划结束→今天）、深蓝=已流逝、浅蓝=剩余。只有两段的表看不出"拖了多久"。
  - 看板并排显示「已完成(状态)」与「已登记实际结束」两个数，两者不等就说明有人标了完成却没填日期。
- **工期固定拆两列，两个数字都要露出来**（这是被用户明确要求的口径，别只留一个）：
  - `工期(工作日)`：**排期依据**，手工填净工作日。资源只能在工作日投入，排产、周会跟进都看它。
  - `工期(自然日)`：`=(实际或计划)结束-开始+1`，公式自动、灰字，**对外承诺与合同交期**用它。
  - 同一窗口两个数永远差一截：**89 个自然日的交付窗口，实际只有 64 个工作日**（占比 72%）。只写一个数，就会在"排期"和"对客户"之间来回打架。
  - 计划结束只由工作日推出，不手填：`=IF(OR($E9="",$F9=""),"",WORKDAY($E9-1,MAX(1,$F9-IFERROR(COUNTIFS(补班,">="&$E9,补班,"<="&WORKDAY($E9-1,$F9,节假日)),0)),节假日))`
    —— `WORKDAY` 跳过周末与法定节假日；最后那层 `COUNTIFS(补班…)` 把调休上班日（周六日上班）计回工时，否则每遇一个补班日就多算 1 天。
  - 目标日落在周末/节假日时自动前移到最后工作日（#40 交付 02-28 是周日 → 02-26），在备注里写明。
  - 自动预警 `=IF($H9<>"","✔ 已完成",IF($K9="已完成","⚠ 待填实际日期",IF(OR($E9="",$F9=""),"○ 未排期",IF(TODAY()>$G9,"⚠ 已延期",IF(TODAY()>=$E9,"● 进行中","○ 未开始")))))`
  - 看板里「已完成(状态)」只按 K 列统计，另设「已登记实际结束」按 H 列统计，两者不等即有人漏填日期；「未完成已超期」是子集，不参与相加。
  - 看板可加「距交付日剩余工作日」`=MAX(0,NETWORKDAYS(TODAY(),交付日,节假日))`，每天打开就知道还剩几天。
- 甘特条条件格式：规则顺序即优先级，**非工作日规则放最后**用浅灰压掉周末与节假日，这样条形自然出现断口（补班日仍上色）。全部带 `ISNUMBER($G9)` 守卫。
- 里程碑用【备注】列写含"里程碑"的文字触发，深红方块落在结束日。
- Sheet 固定四页：`项目计划与甘特图`、`工作日历`、`交付倒排校验`、`使用说明`。
  - `工作日历`：左表放节假日、右表放调休补班，`C2` 是「工期口径」下拉（工作日 / 自然日）；命名区域 `节假日` / `补班` / `工期口径` 供主表公式引用。改假期只改这一页。
  - `交付倒排校验`：`NETWORKDAYS(计划完成, 交付日, 节假日)-1` 算富余，负值即超期；另附一段「自然日 → 工作日」换算，防止拿日历天数当工期。
- 保存后须 `wb.calculation.fullCalcOnLoad = True`，否则 Excel 打开时公式无缓存值。
- **产物落盘必须绕开公司加密驱动**：驱动按扩展名拦截 python 写出的 `.xlsx`（首部变成 `%TSD-Header`），Excel/WPS 打不开、git 里也是密文。脚本统一调用 `save_unencrypted()`：先 `wb.save('xxx.xlsx.zip')`，再由 PowerShell `Move-Item` 改名成 `.xlsx`（改名不重写内容，产物是普通 `PK` 开头的 xlsx，脚本末尾还会自检首字节）。其它 python 生成的 xlsx（周报、报审表等）同理，别直接 `wb.save('*.xlsx')`。原理与排查见《加密环境下生成Office文件_SKILL.md》。
- **验收方法**：用 Excel COM 打开重算，把每行结束日期与 Python 逐日推算结果比对（必须 0 差异），再抽查几个甘特格的条件格式布尔值（普通日 False、周六 True、补班日 False、节假日 True）。

## 五、维护流程（SOP）

1. 与用户确认任务清单：负责人、起止日期、状态、里程碑、依赖关系（谁承接谁）。
2. 更新 HTML：设置 `RANGE` / `TODAY` / `TASKS`，并同步文件名的日期与头部"更新时间"、`renderMiles` 里程碑、`renderNotes` 排期说明。
3. 同步脚本 `generate_anlu_gantt_xlsx_new.py` 内的 `TASKS` / `MILESTONES` 数据，运行脚本生成 xlsx。
   - 紫荆芯界 / 闪迪走智能甘特图脚本：只改脚本里的 `DATA`（行号 → 序号/任务/责任人/日期/工期/状态/备注），重跑 `python generate_zijing_schedule_xlsx.py YYYYMMDD`（或 `generate_sandisk_schedule_xlsx.py`），版本号 +1，旧版保留不删。
   - 改完务必用 Excel/WPS 打开确认看板 B4 的项数与状态分项能对上，且无 #VALUE! / #REF!。
4. 验证：
   - 浏览器打开 HTML：任务条位置/颜色正确、左列与右轨逐行对齐、依赖标记齐全、自适应宽度正常、无 JS 报错。
   - 读取 xlsx：甘特条覆盖日期范围正确、表头/颜色/冻结符合规范。
5. 归档：HTML 与 XLSX 均放 `01_甘特图/`，脚本放 `02_脚本/`。
6. **提交前先确认**：产物归档后按《Git分模块提交规范》分模块提交，**提交 / 推送前先询问用户是否执行**，确认后再操作，不得自动提交 / 推送。
