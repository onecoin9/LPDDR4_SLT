# Git 分模块提交规范（SKILL）

> 用途：固化 **Git 分模块提交**的标准流程与约定，确保每次提交职责单一、历史清晰、便于 review 与追溯。
> 适用：本仓库所有代码 / 文档 / 产物变更的 Git 提交。
> 关联规范：《COLLABORATION.md》第 1 节（提交格式）、第 4 节（文件夹归档规范）。

---

## 一、核心原则

1. **一个提交 = 一个逻辑模块**：每次提交只包含一个主题（如面试题库、周报月报、工具整理），**禁止 `git add -A` 一次性混提全部改动**。
2. **先规划后提交**：提交前先 `git status` 查看全部改动，按模块拆分规划后再逐个提交。
3. **类型 + 范围 + 中文描述**：遵循 Conventional Commits 中文格式（与《COLLABORATION.md》第 1 节一致）。
4. **提交后自检**：每模块提交完成后执行 `git status`，确认工作区干净、无遗漏文件。
5. **PR 配合**：功能分支分模块提交 → 推送 → 创建 PR，review 可逐模块查看。
6. **提交前先确认（必须）**：分模块提交完成后，**必须先询问用户是否提交并推送**，得到明确确认后再执行 `git push`；未经用户确认不得自动提交 / 推送。

---

## 二、提交格式

```
<类型>(<范围>): <描述>
```

| 类型 | 说明 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 修补 bug |
| `docs` | 文档（面试清单、规范、报告等） |
| `refactor` | 重构（目录整理、结构拆分，非新增功能） |
| `perf` | 性能优化 |
| `style` | 格式（不影响运行的变动） |
| `test` | 增加测试 |
| `chore` | 构建过程或辅助工具的变动 |
| `revert` | 回退提交（须注明被回退的 commit 号） |

**示例：**
- `docs: 新增罗思琴/刘女士面试问题清单与杨星面试评价表，更新面试评价汇总`
- `docs: 新增第33周周报数据源与产出，更新月度工作报告`
- `refactor: 甘特图工具按文档/脚本/甘特图目录归类，新增安路甘特图20260817`

## 三、模块划分方法

按**主题 / 目录 / 功能**拆分。常用模块划分参考：

| 模块 | 涉及路径示例 | 建议类型 |
| --- | --- | --- |
| 面试题库 | `01_招聘与面试/.../面试题库/`、`面试评价表` | `docs` |
| 周报月报 | `05_绩效与团队管理/周报月报/` | `docs` |
| 项目管理工具整理 | `03_项目管理与模板/05_项目管理工具/` | `refactor` |
| 项目计划 / 交付 | `03_项目管理与模板/01_项目目录/` | `docs` |
| 知识积累 | `00_技术知识积累/`（除技能规范） | `docs` |
| 技能规范 | `00_技术知识积累/00_技能规范/`、`COLLABORATION.md` | `docs` |

> 单一主题跨多个目录 → 按"主题"聚合提交；单目录含多个主题 → 按"主题"拆分提交。

## 四、标准流程

1. `git status` — 查看全部改动（modified / deleted / untracked），规划模块划分。
2. 逐模块执行：`git add <模块路径1> <模块路径2> ...`
3. 逐模块提交：`git commit -m "<类型>(<范围>): <描述>"`
4. `git log --oneline main..HEAD` — 确认提交历史按模块清晰排列。
5. `git status` — 确认工作区干净、无遗漏。
6. 推送：`git push`（首次推送用 `git push --set-upstream origin <分支>`）。
7. **提交前先确认（必须）**：提交 / 推送前**先询问用户是否执行**，用户确认后再提交并 `git push`；推送后再 `git status` 确认与远端同步（up to date / 干净）。

---

## 五、注意事项

- **不要用 `git add -A` 一次性提交全部改动**；仅当全部改动确认属于单一模块时才可使用。
- 文件移动 / 重命名：Git 自动识别为 `R`（rename），无需特殊处理；提交时确认显示为 `R` 而非 `D + A`。
- 二进制文件（.xlsx / .html 等）：正常 add 提交即可，提交信息注明文件用途。
- 已推送分支改写提交历史时，用 `git push --force-with-lease`（仅限 PR 未合并的独立功能分支）。
- 若需重新拆分已提交内容：`git reset main`（保留工作区改动）后按新模块重新 `add` + `commit`。
- 新生成文件必须归入对应类别目录（见《COLLABORATION.md》第 4 节归档规范），不得散落工作区根目录。
