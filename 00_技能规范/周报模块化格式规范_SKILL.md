# 周报模块化格式规范（SKILL）

> 用途：固化月度工作报告 / 周报 / 邮件正文 / xlsx 的**模块化组织格式**，供 AI 协作生成时统一遵循。
> 适用目录：`05_绩效与团队管理/周报月报/`

---

## 一、为什么模块化

月度报告不按"项目编号平铺"，而是按**模块分组**组织，便于领导快速定位重点：

- 每个模块有清晰标题（一、二、三…）
- 模块内部按项目逐条列出进展
- 周报正文、邮件正文、xlsx 三份输出结构完全一致

---

## 二、标准模块划分

| 顺序 | 模块名 | 典型包含项目 |
| --- | --- | --- |
| 一 | **核心项目** | 金泰克 Nand SLT、晶存 BGA315、安路 FPGA BI、武汉芯源 PSV 等研发/最高优先级项目 |
| 二 | **实验室搭建** | 中钢实验室建设、ATE 实验室搭建 |
| 三 | **DLS 系列项目（验收回款）** | DLS LPDDR4X、DLS 58000-T1、迪洛斯六面检 等验收回款类 |
| 四 | **自动化项目（负责人：谢波）** | 惠存常温/常高温、科摩斯、KMS、JC 三温、CHY 等自动化设备 |
| 五 | **未立项项目** | SD 高可靠性 SLT 等未立项跟进 |
| 六 | **综合管理** | 面试、简历筛选、ERP 物料入库等管理事务 |

> 模块可随当周实际项目动态增减，但应保持「核心 → 实验室 → DLS → 自动化 → 未立项 → 综合管理」的阅读顺序。

## 三、数据文件格式（推荐 `modules`）

在 `02_周报数据源/week_<周数>_data.py` 中，**用 `modules` 结构表达模块化工作**：

```python
author = '崔永元'
date_range = '2026年7月27日 - 2026年8月2日'
append_to_monthly = False   # True 自动追加月报；该周已手动写好则设 False
monthly_report_path = r"d:\arcoview's documents\common-assets\05_绩效与团队管理\周报月报\04_月报\2026年月度工作报告_崔永元.md"

# 可选：邮件正文开头的一句话总结（只写「工作重点主要集中在」后面的部分，脚本自动补括号与句号）
summary = '金泰克项目自动机交付节点推进、晶存项目验收回款，以及实验室搭建物料跟进等事项上'

modules = [
    {
        'name': '一、核心项目',
        'projects': [
            {
                'project': '金泰克 Nand SLT (26098)',
                'tasks': [
                    '· 自动机部分：低温（两个测试盒无冷水机）需赶交期至 0830 交货',
                    '· 电测系统：BGA154 昂科内部无明显进展，Tenafe 端已调通',
                ],
            },
            # ...更多项目
        ],
    },
    # ...更多模块
]

risks = [
    {
        'risk': '风险项名称',
        'support': '描述与支持需求',
    },
]

plans = [
    {
        'project': '金泰克项目',
        'tasks': [
            '· 跟进低温自动机 0830 交期节点',
        ],
    },
]
```

**规则：**

1. `tasks` 一律用列表，每条以 `·` 开头（脚本自动兼容字符串旧格式）。
2. 有 `modules` 时脚本优先用模块化输出；`works` 作为向后兼容字段可留空。
3. `risks` 每条必须带 `support`。
4. `plans` 保留可执行事项，不写空话。
5. `summary` 为可选的一句话总结，只写「工作重点主要集中在」之后的内容（以「……等事项上」收尾）；填写后邮件正文（含月报内嵌的邮件正文代码块）开头固定输出「本周（第N周，周期）的工作重点主要集中在{summary}。」+「以下是具体工作复盘：」，不填则回退为「本周（……）工作情况如下：」。

## 四、生成流程

```bash
cd "05_绩效与团队管理/周报月报/01_脚本"
python create_weekly_report_quick.py <周数>
# 或显式： python create_weekly_report_quick.py --week <周数>
```

脚本会基于 `week_<周数>_data.py` 自动：

| 输出 | 位置 |
| --- | --- |
| xlsx | `03_周报产出/xlsx/工作报告26年第<周数>周_崔永元.xlsx` |
| 月报追加（append_to_monthly=True 时） | `04_月报/2026年月度工作报告_崔永元.md` |

---

## 五、月报标题约定

脚本替换月报时需匹配标题 **`### 第<周数>周（已填写）`**：

- 若该周月报尚未写入 → 保持 `append_to_monthly = True`，由脚本追加。
- 若该周已手动写好（如第 31 周）→ 设 `append_to_monthly = False`，仅生成 xlsx，避免重复。
- 手动写周报时，建议统一使用 `### 第<周数>周（已填写）` 标题，便于后续脚本幂等替换。

## 六、邮件正文

邮件正文结构与周报正文一致，按「一、核心项目 / 二、实验室搭建 / …」模块组织。

开头统一为「一句话总结」开场（与 `summary` 字段联动），即：

```text
Hi 彭总，

    本周（2026年第<周数>周，<周期>）的工作重点主要集中在 A、B、C，以及 D 等事项上。
    以下是具体工作复盘：
```

### 6.1 Markdown 表格版（写入月报）

「本周工作完成情况」按模块用 Markdown 表格（每模块一个两列表：`项目 | 本周进展`）；风险提示、下周待办保留列表形式，方便领导快速扫读。

```markdown
**一、核心项目**

| 项目 | 本周进展 |
| --- | --- |
| 金泰克 Nand SLT (26098) | ①自动机：…；②电测：…；③软件：… |
| 晶存 BGA315 (25074) | … |
```

### 6.2 HTML 表格版（钉钉邮件用）

发钉钉邮件时，额外生成独立 HTML 文件（如 `03_周报产出/第31周邮件正文_崔永元.html`），用**内联样式表格**（表头底色、边框、模块合并单元格），打开后 `Ctrl+A 全选 → Ctrl+C 复制 → 钉钉邮件正文粘贴`，表格格式可保留。

- 表 1：本周工作完成情况（模块合并单元格 | 项目 | 本周进展）
- 表 2：风险提示（风险项 | 描述与支持需求）
- 表 3：下周待办（序号 | 模块 | 待办事项）

参考：`03_周报产出/第31周邮件正文_崔永元.html`
