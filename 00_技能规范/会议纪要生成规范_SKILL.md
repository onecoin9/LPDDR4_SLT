## 二、内部版结构

### 2.1 V2 版式（当前默认，`xxx_会议纪要模板_V2.1_20261106.xlsx`）

**单 Sheet：`会议纪要`**（已去掉 `0_History` 版本履历页，一页到底）

- 页眉：公司名（**A1:I1 合并**，跨全宽居中）
- **会议信息区（7 行，A 列浅灰标签 + B:I 合并取值）**：时间 | 项目 | 会议主题 | 会议类型 | 召集人 | 与会人 | 会议链接
  - 会议类型为下拉：战略决策会 / 项目对齐会或产品评审会 / 专题技术讨论与分享培训会 / 日常对齐会(晨会周会月会) / 客户需求沟通澄清会 / 情况通报及政策宣导会 / 突发应急会
  - **会议链接写两行**：`会议号：XXXX` + `入会链接：https://meeting.dingtalk.com/j/XXXX`（行高 50，B 列单元格已设自动换行）
  - 与会人未确认时写 `TBD（QC、FAE、质量、项目组干系人）`，不要把岗位列表省成空
- **会 议 纪 要**（A11:I11 合并标题带）
- **单张决议表（9 列，一张表搞定，不再拆"决议表 + 任务表"）**：
  序号 | 议题项 | 议题子项 | 决议描述 / 遗留事项 | 责任人 | 目标时间 | 实际完成时间 | **任务状态** | 备注 / 附件
- **议题项纵向合并**：同一议题的多条子项，A 列（序号）与 B 列（议题项）上下合并成一个议题块，序号按议题编号
- **任务状态**：`待开始`（灰 #EDEDED） / `未完成`（蓝 #BDD7EE） / `已完成`（绿 #C6EFCE），H 列为下拉 + 条件格式
- **填写约定**（写在表末灰色图例行）：责任人＝`岗位 / 姓名`（如 `QC / 张三`、`FAE / 李四`），**未定一律填 TBD**；目标时间未定填 TBD；实际完成时间仅「已完成」时填
- **行高**：示例行 50、空白待填行 40，保证多行决议描述不被压扁
- 表末一行灰色小字图例说明三种状态的颜色 + 上述填写约定
- 篇幅约束：**一场会 6~10 行，一个议题块 1~4 条**；描述写"结论 + 量化口径"，不复述讨论过程

> **V2.1 相对 V2.0 的改动**（2026-11-06，依据 ABI3.0 常高温机台出货前对齐会议实例回灌）：页眉合并改为 A1:I1；会议链接改为「会议号 + 入会链接」双行、行高 50；新增责任人「岗位/姓名」与 TBD 填写约定；与会人补「人员未确认先填 TBD」提示；示例行高 38→50、空白行 26→40。

### 2.2 V1 版式（旧版，仅存档）

- 多议题分表（一、二、三…每议题一张 8 列决议表）+ 独立的"三、议题：TBD"6 列任务表
- 结构偏繁琐（同一场会要维护 2 种表头、多张大标题行），新纪要**不再采用**

## 三、客户版结构（客户周度进度汇报）

- **汇报信息**：项目 | 汇报周期 | 汇报人 | 客户对接人 | 日期
- **一、本周进度**：序号 | **模块** | 工作项 / 内容 | 本周进展说明 | **责任人** | **状态**（下拉：已完成/进行中/待办/延期）

## 四、xlsx 生成要点（openpyxl）

### 4.1 状态下拉（DataValidation）

状态列必须做成 Excel 下拉，用 `DataValidation`：

```python
from openpyxl.worksheet.datavalidation import DataValidation
dv = DataValidation(type="list", formula1='"待开始,未完成,已完成"',
                    allow_blank=True, showErrorMessage=True,
                    errorTitle='状态无效', error='请选择：待开始 / 未完成 / 已完成')
ws.add_data_validation(dv)
dv.add('H13:H20')   # V2 版式：任务状态在 H 列
```

- 内部版（V2）状态值：`待开始,未完成,已完成`
- 内部版（V1 旧版）：`未开始,进行中,已完成`（仅存量文件保留）
- 客户版状态值：`已完成,进行中,待办,延期`

### 4.2 合并单元格注意

**必须先 `merge_cells` 再写左上角单元格**，否则写入 MergedCell 会报 `value is read-only`：

```python
ws.merge_cells(start_row=r, start_column=c1, end_row=r, end_column=c2)
ws.cell(row=r, column=c1, value=v)   # 写合并区左上角
```

> V2 版式的"议题项纵向合并"同样适用于此规则：先写满所有数据行，再按议题分组 merge A/B 两列，最后只回写合并区左上角（序号 + 议题项）。

### 4.3 样式规范

- 表头：浅灰填充 `#DBDBDB` + 黑色加粗居中（V2）
- 标签列：浅灰填充 `#D9D9D9` + 加粗
- 章节标题带（"会 议 纪 要"）：浅蓝填充 `#EAF0F7` + 深蓝文字 `#1E3A5F`，跨全宽合并
- 边框：**黑色细线 `#000000`**（thin），列宽按内容、数据行高 26~40（按正文长度估算）
  - ⚠️ 不要用浅灰 `#B7B7B7`：模板 V2.1 的底稿是浅灰，屏幕缩放后几乎看不见，会被当成「表格没有边框」；生成时统一把四边改黑
- 生成脚本可用一次性代码执行，目录只保留 xlsx 产物（遵循归档规范）

### 4.4 状态列条件格式（必须）

状态列除下拉外，**必须加 Excel 条件格式（CellIsRule）实现变色**，不得只有纯文字：

```python
from openpyxl.formatting.rule import CellIsRule
from openpyxl.styles import PatternFill, Font

# V2 版式：任务状态在 H 列。已完成 → 绿；未完成 → 蓝；待开始 → 灰
# 注意：dxf 差分样式的 solid 填充必须 fgColor 与 bgColor 同时给出，且用 8 位 ARGB（FF 前缀），
# 否则 Excel 里底色不显示。
for value, bg, fg in [('已完成', 'C6EFCE', '006100'),
                      ('未完成', 'BDD7EE', '0B6BCF'),
                      ('待开始', 'EDEDED', '8A8F99')]:
    ws.conditional_formatting.add(
        'H13:H20',
        CellIsRule(operator='equal', formula=['"%s"' % value],
                   fill=PatternFill('solid', fgColor='FF' + bg, bgColor='FF' + bg),
                   font=Font(color='FF' + fg, bold=True)))
```

- 配色规范（V2）：**已完成=绿（#C6EFCE/深绿字）、未完成=蓝（#BDD7EE/深蓝字）、待开始=灰（#EDEDED/灰字）**
- 若某场会想用"未完成=红"表示逾期，把 `BDD7EE/0B6BCF` 换成 `FFC7CE/9C0006` 即可（其余不变）
- 客户版（已完成/进行中/待办/延期）：已完成绿、进行中蓝、待办灰、延期红（#FFC7CE/深红字）
- **每个状态列范围都要加规则**：V2 在 H 列；V1 决议表 G 列、任务表 F 列，按实际行号应用
- 下拉范围要覆盖**空白待填行**，否则新增行没有下拉与变色

## 五、HTML 生成要点

- 单 HTML 文件、内联 CSS，A4 打印友好（`@page A4` + `@media print`）
- 状态列用 `<select>` 下拉（与 xlsx 下拉对应）：
  ```html
  <select class="sel"><option>已完成</option><option>进行中</option><option>待办</option><option>延期</option></select>
  ```
- **状态列必须变色**：`<select>` 下拉需加 JS（`onchange`），选中不同状态时动态改变背景与文字颜色；也可用徽章 `<span class="st-badge">` 呈现。纯文字下拉不可接受。
- 状态徽章配色：已完成绿 / 未完成蓝 / 待开始灰（客户版另有：待办灰 / 延期红）
- 浏览器打开验证表格渲染、下拉与**变色效果**后再交付

## 六、生成流程

1. **询问文件格式（必做）**：生成前先询问用户需要哪种文件，**不要默认全部生成**。
   - `.md`：纯文本纪要，便于阅读、二次编辑与 Git 归档
   - `.html`：A4 打印友好，含状态下拉，适合展示 / 打印 / 存档
   - `.xlsx`：Excel 版（**默认走 V2 模板**），含状态下拉（DataValidation）+ 条件格式变色，适合在线协作填写
   - 可多选（如 `.md + .xlsx`），但**必须由用户明确指定**，不得擅自生成用户未要求的格式。
2. 确认场景：**内部会议**（内部版 V2）还是**客户周度汇报**（客户版）。
3. 收集会议信息（项目/时间/参会人/议题/决议/待办/风险）。
4. 按对应结构生成**用户指定格式**的产物（HTML 需浏览器验证，xlsx 需 openpyxl + 状态下拉 + 条件格式）。
   - **克制篇幅**：一场会以 6~10 行为宜，一个议题块 1~4 条子项；描述写"结论 + 量化口径"，不复述讨论过程。
5. 存放到 `01_会议纪要/<项目文件夹>/<YYYY-MM>/`，命名规范：`<日期>_<项目>_<主题>会议纪要(.md / .html / .xlsx)`；判断不了项目归属放 `00_跨项目与内部/`。
6. 回写 `00_会议纪要索引.md`（对应项目表末行追加，写清一句话重点 + 关键待办）。
7. **提交前先确认**：产物归档后按《Git分模块提交规范》分模块提交，**提交 / 推送前先询问用户是否执行**，确认后再操作，不得自动提交。

## 七、目录管理（项目 → 月份 两级）

`01_会议纪要/` 下**模板、索引、真实纪要三者分离**，真实纪要按 **项目 → 月份** 归档：

```
01_会议纪要/
├─ 00_会议纪要索引.md          ← 索引（必看，含重点速览 / 跨月红线 / 按项目表）
├─ 模板/                        ← 可复用模板 + 示例
│   ├─ xxx_会议纪要模板_V2.1_20261106.xlsx   ← 当前默认（单 Sheet，状态彩色）
│   ├─ 会议纪要模板_需求对齐版.html / .xlsx   ← V1 旧版，仅存档
│   ├─ 客户周度进度汇报模板.html / .xlsx
│   └─ 会议纪要模板_示例_*.html
├─ 00_跨项目与内部/             ← 架构、选型、验收、技术交流等跨项目会议
├─ 01_金泰克NAND_SLT/
├─ 02_安路FPGA_BI/
├─ 03_紫荆芯界/
├─ 04_曦望V9000_ABI/
├─ 05_Delos软件/
└─ 06_SRT子板_特纳飞/
    └─ 2026-10/                 ← 二级：每个月一个子目录
```

- 项目文件夹用**两位数字前缀**（`00` 跨项目、`01` 起为具体项目），保证排序稳定；新项目按序追加。
- 判断不了归属的会议放 `00_跨项目与内部/`，并在索引里注明；**不要**硬塞进某个项目。
- 归档后必须回写索引：`00_会议纪要索引.md` 对应项目表末行追加（一句话重点 + 关键待办）。
- 模板改动只放 `模板/`；每次新增 / 修改模板后同步更新本规范。

## 八、触发话术（用户怎么说 → 我怎么做）
